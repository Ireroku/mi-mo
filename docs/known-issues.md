# 既知の課題

実装済みの機能に残っている課題の一覧。着手する前にここを読み、直した項目はこの一覧から消す。機能が実装済みかどうかは、リポジトリ直下の [README.md](../README.md) だけが持つ。

各項目は「起きること」「場所」「直す方向」の順に書く。直す方向は提案で、確定した設計ではない。着手する時点で対応する [実装指示書](./impl/README.md) を先に更新する。

## 表示

### Moodle へ差し込む部品の文字が小さい箇所が残っている

- 起きること: 時間割（ホーム）の表は 12px、表の中の補足は 10px で描かれる。上部メニューの時計の日付と、カウントダウンのラベルも 12px になっている。設定画面は 13px 以上へ揃えたが、これらは揃えていない
- 場所: `src/features/timetable/Timetable.svelte`、`src/features/menu/clock.svelte`、`src/features/menu/countdownBadge.svelte`
- 直す方向: 実際の Moodle の画面で幅と折り返しを見ながら、文字を大きくする。表は列の幅が決まっているため、見ずに変えると崩れる

### 時間割の配色が OS のダークモードに引きずられる

- 起きること: 配色に白・水色・ピンク・緑を選んでいても、OS がダークの間は暗い色の組へ変わる。黒も文字色が OS の配色に追従する場合がある。Moodle 自体は明るいままのため、選んだ色と違う見た目になる。配色「Moodle」では起きない
- 場所: `src/features/timetable/Timetable.svelte` の `@media (prefers-color-scheme: dark)` の定義と、`text-foreground` のトークン
- 直す方向: 修正する予定。選んだ色を OS の配色にかかわらずそのまま出す。直す時は [`impl/timetable/panel.md`](./impl/timetable/panel.md) の「配色」と決めごとを先に書き換える

## 信頼性

### Firefox のポップアップでファイルを選ぶと閉じる恐れがある

- 起きること: Firefox では、ポップアップからファイル選択のダイアログを開くとポップアップが閉じる場合がある。閉じると、バックアップ・時間割・挨拶のメッセージの「ファイルから読み込む」が終わらない。実機では未確認
- 場所: `src/features/settings/BackupButtons.svelte`（バックアップと、`fields/TimetableFooter.svelte` から使う時間割）、`src/features/settings/fields/GreetingMessagesField.svelte`
- 直す方向: 実機で起きることを確かめる。起きる場合は、Firefox のポップアップでは読み込みをオプション画面へ案内する

### background が保存先のファイル名を確かめていない

- 起きること: 保存のメッセージを受けた background は、`url` が文字列かどうかだけを見て、`filename` をそのまま `browser.downloads.download` へ渡す。メッセージを送るのは自分の content script だけのため、今は害が無い。送り手が増えた時や、ファイル名を組み立てる処理に誤りがあった時に、意図しない名前や階層で保存される
- 場所: `src/entrypoints/background.ts` の `onMessage` の受け口
- 直す方向: `filename` も文字列であることを確かめ、`..` や絶対パスを含む名前は捨てる。ファイル名を作る処理は [`impl/utils/filename.md`](./impl/utils/filename.md) にあり、同じ規則で検証する

### 時限表に無い番号の授業は時間割に出ない

- 起きること: 版 1 の頃に時限表を5行より少なくしていて、消した行の位置にも授業を入れていた場合、移行後はその授業が時間割にも設定画面にも出ない。値は保存に残っている
- 場所: `src/utils/periods.ts` の `migratePeriodsFromV1`、`src/utils/settings.ts` の `periodTableSetting` の移行
- 直す方向: 当てはまる人は少ないと見て、残す。困る場合は、移行の時に時間割から授業のある番号を集め、時限表に無ければ時刻の空いた枠として足す。時限表と時間割は別の保存項目のため、移行で両方を読む形になる

### 設定画面を2つ同時に開くと後から保存した側が勝つ

- 起きること: ポップアップと設定ページで同じグループの別の項目を変えると、先に保存した変更が消える場合がある
- 場所: `src/features/settings/types.ts` の `defineGroup` が作る `write`。読む・差し替える・書くの3手になっている
- 直す方向: 1つの画面の中では `SettingsPanel` が保存を直列化している。画面をまたぐ競合は、実際に困る利用が出るまで扱わない

### 日付をまたいでも表示が更新されない

- 起きること: ページを開いたまま日付が変わると、時間割の「今日」とマイコースの今日順が前日のまま残る
- 場所: `src/features/timetable/Timetable.svelte`、`src/features/myCourses/todayOrder.ts`
- 直す方向: ページを読み込み直すと直る。タブへ戻った時に日付を取り直す処理は、必要性が確かめられてから足す

## 保守性

### カウントダウンの粒度を切り替える閾値を設定できない

- 起きること: 秒刻み・分刻み・日数表示へ切り替わる残り時間（15分・24時間・7日）が固定値になっている
- 場所: `src/features/menu/countdownBadge.logic.ts` の `formatRemaining`
- 直す方向: `CountdownConfig` へ閾値を足し、[`impl/settings/menuFields.md`](./impl/settings/menuFields.md) のカウントダウン編集へ入力欄を足す

## 対応しない環境

- **Safari では資料の保存とセクションの書き出しが動かない。** `browser.downloads` が無いため。理由と差し替えの方針は [`impl/utils/download.md`](./impl/utils/download.md) にある
