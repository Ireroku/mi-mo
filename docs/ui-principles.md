# UI の考え方

mi-mo の画面と文言を作る時の判断の軸。設定画面と、Moodle へ差し込む部品の両方に当てはまる。画面を作る前と、文言を書く前に読む。

個々の部品の寸法やクラスは [実装指示書](./impl/README.md) が持つ。ここには、それらを決める時の理由だけを置く。

## 根にある考え

**画面に置くものは、どれも利用者の注意と面積を使う。使った分に見合う情報を運ぶものだけを置く。**

文字、色、強調、設定項目、ウィジェットの幅は、すべて同じ物差しで測る。「これを消すと、利用者は何かを知り損ねるか」に「いいえ」と答えられるものは置かない。

下の原則は、どれもこの1つから出る。迷った時は原則の文面ではなく、この物差しへ戻る。

## 原則

### 1. 文字は、情報が増える時にだけ置く

デザインや文脈から伝わること、利用者が期待する通りの動作は書かない。

| 書かないもの | 理由 |
|---|---|
| 「変更はすぐに保存されます」 | すぐ保存されるのは利用者が期待する動作で、説明が情報を増やさない |
| 「ホーム」タブの中の項目に付く「ホームの」 | タブが既に場所を示している |
| 「時計のオプション」の中の「秒を表示する」の「を表示する」 | 見出しとスイッチが、表示の入り切りであることを示している。項目は「秒」で足りる |
| 画面の名前「mi-mo の設定」 | ポップアップを開いた時点で、何の画面かは分かっている。その場所は「有効」スイッチに使う |

逆に、期待と違う動作は書く。設定が Moodle のページを読み込み直すまで効かないことは期待に反するため、「変更を適用するにはページを再読み込みしてください」を最上部に置く。

### 2. 強調は、区別が増える時にだけ使う

目立たせること自体は情報を増やさない。色、太さ、大きさを変えるのは、それで階層や状態の違いが伝わる時に限る。

- 階層は色ではなく太さで示す。カードの見出しは、行と同じ色・同じ大きさの太字にする
- デザインで伝わることを、文字で重ねて説明しない。強調する意図がある場合だけ、文字を足す
- 行の中の主従は、色の濃淡だけで付ける

### 3. 設定項目も、価値に見合うものだけを置く

設定を1つ足すと、すべての利用者が読む行が1つ増える。変える人がほとんどいない値や、変えても違いが分からない値は、設定にせず固定する。

無効にした機能の詳細は畳む。一覧や表の中身は、押した人だけが別の画面で読む。

### 4. 同じものは、同じ形で書く

形が揃っていると、利用者は1つ覚えれば残りを読まずに済む。揃っていない箇所は、意味の違いがあると受け取られる。

- 説明（`description`）の文末は「〜します」に揃える
- 同じものを指す語は、画面をまたいで同じ語にする
- 行の形（左に名前、右にコントロール）を全項目で揃える
- 新しい文言を足す時は、隣の行と並べて読み、形が揃っているかを見る

### 5. 文は、読む順に意味が取れる形にする

- 主語と述語を近づける。間に修飾を挟まない
- 助詞で語を細かく切らず、ひとまとまりの語として読める形にする
- 多くの人にとって重要でない情報は後ろへ置く。拡張子は末尾に括弧で添える（「カレンダー予定ファイルとして書き出す (.ics)」）
- 一般の人が使う語を選ぶ。実装の用語を画面に出さない

### 6. 固有の名前は、場所と一緒に示す

「時間割」のように mi-mo が決めた名前は、利用者にとって初めて見る語になる。別の場所の設定を指す時は、名前だけでなく、どこにあるかを書く（「「ホーム」タブの時間割情報のコースURLを使用します」）。

### 7. 設定は、効果が現れる場所の文脈で区切る

保存先や実装の単位ではなく、利用者がその設定を探す場所で分ける。

- タブは、効果が現れる Moodle の画面で分ける
- 時限表は時計と保存先を共有するが、時刻を決める動機は時間割の入力にあるため、時間割のカードに置く
- 「今日の授業を先頭に出す」は時間割の情報を使うが、効果が出るのはマイコースのため、「コース」タブに置く
- どの場所にも効くもの（全体のスイッチ）は、タブの外の最上部に置く

### 8. 面積は借り物として扱う

ポップアップも Moodle の上部メニューも、他のものと分け合う場所になる。mi-mo の部品は、要る分だけを取る。

- ポップアップは、他の拡張機能と同じ程度の小ささ（380×560px）に収める
- 横幅が足りない時は、二段にする、省略する、優先度の低いものから消す、の順で譲る
- Moodle の画面に差し込む部品は、Moodle の配色と揃え、周りから浮かない色を既定にする

### 9. 今いる場所を見失わせない

- 詳細は、その場で広げずに別の画面へ進める。その場で広げると前後の行が押し出され、位置を見失う
- 進んだ先には、パンくずと「戻る」を出す
- 戻った時は、元のスクロール位置へ戻す

### 10. 操作には、動きで応える

押した結果がどこに現れたかを、動きで示す。進む時は右から、戻る時は左から入れる。行は滑って現れ、選択の印は滑って移る。

動きは短く（150〜200ms）保ち、OS が動きを減らす設定の間は止める。

## 使い方

画面や文言を作ったら、出す前に次を1つずつ当てる。

1. この文字を消すと、利用者は何かを知り損ねるか
2. この強調を外すと、何かの区別が付かなくなるか
3. 隣の行と、語と文末の形が揃っているか
4. 初めて見る人が、この語の指すものと場所を分かるか
5. この項目は、利用者が探す場所に置いてあるか
6. 幅が半分になった時に、何を先に譲るかが決まっているか
7. 押した後、利用者は今どこにいるかを分かるか
