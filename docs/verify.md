# 検証の手順

変更を終えたと言う前に行う確認をここにまとめる。上から順に軽く、下ほど手間がかかる。変更の範囲に応じて、必要な段まで進める。

## 1. 機械的な検査

コードか文書を1行でも変えたら必ず行う。5つすべてが通る状態を保つ。

```sh
pnpm check                     # svelte-check による型と構文の検査
pnpm test                      # Vitest による単体テスト
pnpm build                     # Chrome 向けのビルド
pnpm build:firefox             # Firefox 向けのビルド
python3 scripts/checkdocs.py   # docs の文体とリンク切れ
```

`pnpm check` が通ってもビルドが失敗する場合がある。パスエイリアスの解決が型検査とバンドルで別の設定を見るため。理由は [`impl/README.md`](./impl/README.md) の「パスエイリアス」にある。

permission を足した場合は、生成物の `.output/chrome-mv3/manifest.json` と `.output/firefox-mv3/manifest.json` に宣言が入ったことを見る。

### 自分の Chrome で確かめる

`wxt.config.ts` の `webExt.disabled` により、`pnpm dev` はブラウザを立ち上げない。拡張機能は自分の Chrome へ読み込む。

1. `pnpm dev` を実行する
2. Chrome の `chrome://extensions` でデベロッパーモードを入れ、「パッケージ化されていない拡張機能を読み込む」から `.output/chrome-mv3-dev` を一度だけ読み込む
3. 以後は、dev サーバーが動いている間、ファイルを保存するたびに拡張機能が読み直される。content script を変えると、対象のタブも読み直される

dev ビルドは、localhost への接続と `tabs`・`scripting` の権限を持つ。開発用の Chrome プロファイルへ読み込み、普段のプロファイルには残さない。

## 2. 設定画面だけを確かめる

設定画面（`src/features/settings/`）は Moodle を必要としないため、拡張機能のページとして単体で開いて確かめる。

1. `pnpm dev` を実行し、「自分の Chrome で確かめる」の手順で読み込んだ Chrome を使う
2. ツールバーのアイコンからポップアップを開く。広い画面での見え方は、拡張機能の管理画面から「拡張機能のオプション」を開いて確かめる
3. 次を確かめる

| 確かめること | 見る場所 |
|---|---|
| 項目を操作した直後に値が保存される | 開発者ツールの Application → Extension storage → Local |
| 画面を開き直しても値が残る | ポップアップを閉じて開く |
| 機能を無効にすると、その機能の詳細項目が隠れる | 先頭の行にスイッチがあるカード |
| 一覧や表の行を押すと別の画面へ進み、「戻る」で元の位置へ戻る | 右向きの山形が付いた行 |
| 書き出したバックアップを読み込むと、値が戻る | 「全体」タブの末尾の「バックアップ」 |
| ライトとダークの両方で読める | OS のカラースキームを切り替える |
| コンソールにエラーが出ない | ポップアップを右クリック →「検証」 |

### 拡張機能として読み込まずに開く（開発用のページ）

拡張機能を読み込めないブラウザでも、設定画面を普通のページとして開ける。[known-issues.md](./known-issues.md) の「開発用のページで確認済み」は、このページでの確認を指す。

```sh
pnpm harness                                                  # ビルドして .output/harness を作る
python3 -m http.server 8766 --bind 127.0.0.1 --directory .output/harness
```

`http://localhost:8766/popup.html` でポップアップ、`options.html` でオプション画面が開く。ポップアップの大きさは、ブラウザの幅を 380×560px に絞って見る。

- **仕組み**: [`scripts/harness/build.mjs`](../scripts/harness/build.mjs) が `.output/chrome-mv3` を `.output/harness` へ写し、`popup.html` と `options.html` の `<head>` の先頭へ [`scripts/harness/shim.js`](../scripts/harness/shim.js) を差し込む。`shim.js` は `chrome.storage` を `localStorage` で代用する
- **コードを変えたら `pnpm harness` を実行し直す。** `pnpm dev` の変更は反映されない
- **保存した値は `localStorage` の `mimo-harness-storage` に入る。** 初期状態から見直す場合は、開発者ツールでこのキーを消す
- **確かめられるのは設定画面の見た目と操作だけになる。** content script は動かず、メッセージの送信は何もしない。拡張機能のポップアップの枠での見え方（Firefox や Safari の枠で切れないかなど）は、実際のポップアップで確かめる

## 3. 実際の Moodle で確かめる

Moodle のページへ手を入れる機能は、実機でしか確かめられない。[三重大学 Moodle](https://lms-m41.mie-u.ac.jp/) へのログインが要る。ログインは利用者本人が行う。

1. `pnpm dev`（Firefox は `pnpm dev:firefox`）を実行し、拡張機能を読み込んだブラウザで Moodle へログインする
2. 変更した機能が対象にするページを開く。ページの種類と URL の対応は [`moodle/README.md`](./moodle/README.md) にある
3. 設定を変えた場合は、ページを読み込み直してから見る。設定は読み込み時にだけ反映される
4. 次を確かめる

| 確かめること | 見る場所 |
|---|---|
| 変更した機能が仕様の通りに動く | [`features/`](./features/) の該当する仕様書の「何ができるか」 |
| 同じページで動く他の機能が壊れていない | 下の表 |
| `[mi-mo]` で始まるエラーが出ない | ページの開発者ツールのコンソール |
| 保存に関わる変更では、background 側にもエラーが出ない | 拡張機能の管理画面 → Service Worker の「検証」 |

ページごとに動く機能は次の通り。

| ページ | 動く機能 |
|---|---|
| すべてのページ | 上部メニューの項目・時計・カウントダウン・ロゴ、ヒントボタン、クイックドロワー、フォント、パンくずリスト |
| サイトホーム | 不要な要素の非表示、挨拶、時間割、未ログイン時のログイン部品 |
| マイコース | 今日の授業順、カード全体のクリック、絞り込み検索 |
| コースページ | セクションの並び順・タイトルのリンク・一括開閉、コースインデックスのトグル、評定の埋め込み、出欠ボタンと出席統計、書き出し、資料の一括保存 |

1つの機能が初期化に失敗しても、残りの機能は動く。失敗した機能は `[mi-mo] <機能名>` の形でコンソールへ出る。仕組みは [`impl/utils/runFeature.md`](./impl/utils/runFeature.md) にある。

## 4. Moodle の構造が変わった場合

機能が急に効かなくなった場合、Moodle 側のマークアップが変わった可能性を先に疑う。

1. 対象のページを開発者ツールで開き、[`moodle/`](./moodle/) に記録したセレクタが今も当たるかを見る
2. 変わっていた場合は、[`moodle/`](./moodle/) の資料を先に直す。採取の手順は [`moodle/README.md`](./moodle/README.md) にある
3. その後で機能の指示書とコードを直す

## AIエージェントが確かめる場合

- 1 の検査はそのまま実行する
- 2 の設定画面は、ブラウザを操作できれば「開発用のページ」で確かめられる。タブを切り替えた直後は動きの途中が写るため、2秒ほど待ってから撮る
- 2 のほかの項目と 3 は、拡張機能を読み込んだブラウザを操作できる場合にだけ行う。利用者の Chrome を操作するツール（`claude-in-chrome`）が使え、そこへ `.output/chrome-mv3` が読み込まれていることが条件になる。拡張機能を読み込めないブラウザでは content script が動かないため、Moodle を開いても確認にならない
- ログイン画面が出た場合は、利用者にログインを頼む。パスワードを自分で入力しない
- 条件が揃わない場合は、下の「確認できなかった場合」に従う

## 確認できなかった場合

ログインできない、対象のコースが無いなどの理由で実機の確認ができなかった場合は、確認できなかった項目を [known-issues.md](./known-issues.md) の「実機での確認が済んでいないもの」へ足す。確認したことにしない。
