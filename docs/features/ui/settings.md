# 拡張機能の設定画面

## 何ができるか

mi-mo のすべての設定を GUI で行う画面を用意する。ブラウザのツールバーから開くポップアップには、同じ画面をそのまま表示する。

画面はレスポンシブに作り、ポップアップの狭い幅でも広い画面でも1枚で兼ねる。

設定は、効果が現れる Moodle の画面ごとに「ホーム」「コース」「全体」の3つのタブへ分ける。タブの中では、機能ごとのまとまりをカードにし、よく変える設定を上に置く。機能を無効にしている間は、その機能の詳細を畳む。一覧や表を編集する設定は、一覧には件数だけを見せ、押した時にその設定だけの画面へ進む。進んだ先には、今いる場所を示すパンくずと「戻る」ボタンを出す。

### 全機能の一括オン・オフ

画面の最上部に「有効」スイッチを置く。切ると、設定を残したまま mi-mo のすべての機能が止まる。Moodle のページを読み込み直した時点で効く。

### 設定のバックアップ

すべての設定を1つのファイル（`mi-mo-settings.json`）へ書き出し、そのファイルから読み込み直せる。

## なぜ必要か

隠すメニュー項目・時計の表示内容・カウントダウンの対象といった設定をソースコード内の定数として持つと、変更するたびに拡張機能をビルドし直す必要があり、実質的に開発者しか設定を変えられない。

設定画面を1枚だけ作り、それをポップアップへ流し込む形にすれば、実装も画面も分散しない。Moodle のページ上へ設定ボタンを埋め込むかどうかは、この画面ができた後に決めればよく、機能の本体ではない。

同じ方式を Control Panel for Twitter が採っている。

一括のスイッチは、Moodle の表示が崩れた時に、原因が mi-mo かどうかを切り分けるために使う。拡張機能そのものを無効にする方法では、設定画面も開けなくなる。

バックアップは、拡張機能の入れ直しや別のブラウザへの移行で、時間割や時限表を打ち直さずに済ませるために使う。

## 対象

ブラウザのツールバーから開くポップアップと、拡張機能のオプション画面。

## 設定項目

| 設定 | 内容 |
|---|---|
| 有効 | mi-mo の全機能を動かすかどうか。既定は有効 |

見た目など、この画面自体の設定はない。
