# 機能仕様書

ユーザーから見た機能を1本ずつ記載する。リポジトリ直下の [README.md](../../README.md) の機能一覧の第2階層と1対1で対応する。

## この拡張機能が目指すもの

個々の機能の動機は、多くがここに書く共通の考え方から来ている。各仕様書の「なぜ必要か」では、この共通部分を繰り返さず、その機能に固有の事情だけを書く。

### 不要な要素を視界に入れない

画面に映っているだけで、人はそれを処理してしまう。使わない要素が並んでいると、それだけで脳のリソースを消費し、本当に必要なものを探す負担が増える。

使わない要素を消すことは、見た目の整理ではなく負担の削減として扱う。

### 空いた場所へ必要なものを置く

消すことと足すことは表裏になっている。不要な要素を消せば場所が空き、そこへ本当に何度も見るもの（時刻、締め切りまでの残り時間、よく使うコースへの入口）を置ける。

### 無意識の1クリックを減らす

繰り返す操作は、意識しなくなった後も脳のリソースを使い続ける。ログイン後に毎回「コース一覧」を開くような動作は、回数が多いほど削る価値が大きい。

### 楽しさも動機として扱う

使っていて楽しいことは、それ自体が目的になる。実用上は無くても困らないが気分が変わる、という機能を置いてよい。飽きずに使い続けられることには価値がある。
